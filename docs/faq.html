常见问题

按使用阶段整理了最常遇到的疑问：安装、提取、导出、以及数据安全相关的说明。

提取相关

  • 先按 F5 刷新页面：内容脚本只对安装/刷新之后的页面生效。
  • 确认是在普通网页（http / https）上，浏览器内置页面 （edge://、扩展商店、file:// 等）禁止注入脚本。
  • 检查设置页里的「显示悬浮按钮」是否被关闭；关闭时可用工具栏图标或 Alt+Shift+T 触发提取。
  • 按钮被页面元素遮挡时，可以拖拽到别的位置，或直接使用工具栏图标。
提示里会同时给出「本页共 N 个 <table>、已忽略 M 个」的统计。常见原因与处理方式：
  • 行列太少：单行或单列表格被最小行列阈值过滤。到设置页把「最小有效行数 / 列数」改成 1 后重新提取。
  • 被判定为布局表：关闭设置页的「过滤布局装饰表格」再试一次。
  • 表格在隐藏容器里：例如未激活的标签页内容。切到对应标签页让表格显示出来，或在设置页关闭「跳过隐藏表格」。
  • 表格在 iframe 里：插件目前只扫描顶层文档。可以右键 iframe 内部选择「在框架中打开」后单独提取。
  • 数据还没加载：等表格渲染出来后再点击按钮。
想确认过滤规则是否过严，可以在设置页点击「用当前规则试扫最近浏览的网页」。
  • 合并单元格（rowspan / colspan）会被展开成规整矩阵，跨行跨列的格子只在起始位置保留文本， 其余位置为空，这是为了避免导出后错列。
  • 通过 CSS 隐藏的内容不会导出；<br> 会保留为单元格内的换行。
  • 单表超过 5000 行或 200 列时会截断，预览页会标注「已截断」，需要完整数据可分页后再提取。

导出相关

改用「Excel 兼容 CSV（含 BOM）」格式。它在文件开头写入 UTF-8 BOM 头并使用 CRLF 换行， Excel 可以直接正确识别编码。如果已经导出了普通 CSV，也可以在 Excel 里用「数据 → 从文本/CSV」导入时手动选择 UTF-8。
这是 CSV 的标准转义规则：字段包含逗号、双引号或换行时，整体会用双引号包裹，字段内部的双引号写成两个双引号。 Excel、Python csv 模块等都能正确还原，不需要手工处理。
保存到浏览器的默认下载目录（Edge 默认是「下载」文件夹）。预览页底部状态栏右侧的 「打开下载目录」按钮可以直接跳转。文件名为 page_table_日期_序号.扩展名， 同名文件不会覆盖，浏览器会自动追加序号。
浏览器的批量下载保护机制。选择允许即可，也可以点击地址栏右侧的下载图标， 选择「始终允许此网站下载多个文件」。
合并模式会在每张表格前插入一行分节说明（形如 【001】销售报表 (3 行 × 3 列)）， 表格之间用空行分隔，用 Excel 打开依然可读。建议合并时优先选择 JSON 或 Markdown， 这两种格式的结构化分隔更清晰。
浏览器后台脚本在空闲时可能被回收，长时间停留在预览页后再导出，暂存的数据可能已被清理。 此时回到网页重新点击一次「提取表格」即可；预览页也会自动尝试用页面内的数据完成导出。

数据安全与隐私

提取结果只暂存在会话级存储中（浏览器关闭即清空），并保留最近几次记录供预览页读取； 设置项、按钮位置等偏好保存在本地存储中，可在卸载扩展时一并清除。

故障排查清单

遇到异常时，按下面的顺序逐项确认，通常能解决绝大多数问题：

  1. 刷新页面：安装或更新扩展后，必须刷新目标网页，内容脚本才会被注入。
  2. 确认页面类型：edge://、扩展商店、PDF 内置查看器等页面禁止注入脚本。
  3. 查看错误控制台：在目标网页按 F12 打开开发者工具，看 Console 里是否有 [TableGrab] 开头的日志；扩展自身的日志在 edge://extensions/ → TableGrab 卡片 →「Service Worker」链接中查看。
  4. 调整过滤阈值：设置页 →「表格过滤规则」，把最小行列数改成 1、关闭布局表格过滤后重新提取。
  5. 使用试扫功能：设置页 →「功能自检」→「用当前规则试扫最近浏览的网页」， 它会返回「共发现 N 个表格、通过 M 个」，便于定位是过滤规则的问题还是注入失败的问题。
  6. 重新加载扩展：在扩展管理页刷新卡片；仍未恢复则移除后重新「加载解压缩的扩展」。
仍然无法解决？请记录以下信息再排查：页面地址、浏览器版本、 试扫返回的统计数字、控制台中 [TableGrab] 开头的报错内容。
